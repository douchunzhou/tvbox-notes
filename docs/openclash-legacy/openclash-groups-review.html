一、逐项审查（13 项）

✅ 1. url-test 支持 proxies 字段？ — 正确
proxies 是通用字段，适用于所有分组类型。Mihomo 官方 url-test 示例明确包含 proxies。
来源：Mihomo Wiki - url-test
✅ 2. fallback 支持 proxies 字段？ — 正确
来源：Mihomo Wiki - fallback
✅ 3. lazy: true 在 url-test 中生效？ — 正确
lazy 是通用字段，默认 true。含义："未选择到当前策略组时，不进行测试"。
来源：Mihomo Wiki - 通用字段
✅ 4. include-all: true 与 url-test 兼容？ — 正确
include-all 引入所有代理（含 proxy-providers），但不包括其他代理组。
来源：Mihomo Wiki - include-all
⚠️ 5. use 与 include-all 冗余 — 需修正
include-all 已包含 proxy-providers 节点，use 字段多余。但注意：include-all-providers 会使 use 失效（二者二选一）。
来源：Mihomo Wiki
🔴 6. health-check 只测试 proxies 字段！ — 关键修正
Mihomo 官方明确警告：健康检查的 url 仅对 proxies 字段中的节点有效。通过 use/include-all-providers 引入的节点不会被健康检查。

# 原方案（有问题）：
YouTube:
  type: url-test
  use: [IKUU, 三元]  ← 这些节点不会被健康检查！

# 修正后：
YouTube:
  type: url-test
  include-all: true   ← 引入所有节点用于测速
  proxies: [所有-自动, 香港-自动] ← 手动备选也会被检查
来源：Mihomo Wiki，url 字段说明
✅ 7. tolerance 和 interval 语法 — 正确
tolerance 单位 ms，interval 单位秒。纯数字无后缀。
来源：Mihomo Wiki - url-test
✅ 8. fallback 的 url 和 interval — 正确
fallback 支持健康检查，语法与 url-test 相同。
来源：Mihomo Wiki - fallback
⚠️ 9. OpenClash LuCI 可能覆盖 YAML 设置
LuCI 会覆盖：url、interval、tolerance、smart-conversion。不会覆盖：proxies、include-all（成员列表）。建议在 LuCI 中也确认健康检查设置。
来源：OpenClash 源码 yml_proxys_set.sh
✅ 10. OpenClash 不会自动生成冲突分组
DIRECT / REJECT / GLOBAL 是 Mihomo 核心内置，不是 OpenClash 添加的。
来源：OpenClash 源码 yml_rules_change.sh
✅ 11. url-test 无可用节点时
回退到 proxies 列表第一个可用节点。建议始终保留保底选项。
来源：Mihomo FAQ
✅ 12. 订阅更新不影响分组配置
订阅更新只合并节点到 proxy-providers，不修改 proxy-groups 结构。
来源：OpenClash 源码 yml_proxys_set.sh
⚠️ 13. &auto 模板需显式声明 lazy
虽然默认 true，但显式声明更清晰、更易维护。

四、关键修正说明

💡 核心变化

字段原方案修正后原因
use[IKUU, 三元]删除与 include-all 冗余
include-all❌ 未使用true引入所有节点 + 支持健康检查
lazy未声明true显式声明，减少不必要测速
📝 OpenClash LuCI 注意

修改 YAML 后，到 LuCI → OpenClash → 设置 检查：

  • 健康检查 URL 是否被 LuCI 覆盖（应为 https://www.gstatic.com/generate_204）
  • 检查间隔是否正确（300 秒）
  • "智能分组转换"是否干扰了 url-test 类型
✅ 验证方法

修改后在 OpenClash → 代理 页面检查：

  1. 每个自动分组下方应显示延迟数字（如 "50ms"），说明健康检查在工作
  2. 如果显示 "超时" 或空白，说明健康检查 URL 有问题
  3. 手动切换节点后等 5 分钟，看是否会自动切回（lazy=true 的行为）
