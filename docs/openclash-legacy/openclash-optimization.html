一、配置审计结果

以下基于 oect 实际运行配置与 Mihomo/OpenClash 官方文档最佳实践的对比。

1.1 DNS 配置差距

🔴 严重 缺少 DNS fallback

当前只有国内 DNS 223.5.5.5，没有配置国外 DNS fallback。

后果：国外域名（YouTube、Google 等）的 DNS 查询也走国内 DNS，可能被污染或返回不可达的 IP。

配置项当前值推荐值
nameserver223.5.5.5（明文）DoH 加密 + 多个
fallback❌ 未配置tls://8.8.4.4 + tls://1.1.1.1
fallback-filter❌ 未配置geoip: true, geoip-code: CN
default-nameserver❌ 未配置223.5.5.5 + 119.29.29.29
⚠️ 注意 fake-ip-range 非标准

配置项当前值推荐值
fake-ip-range198.20.0.1/16198.18.0.1/16

虽然能工作，但 198.18.0.0/15 是 IANA 为私网保留的标准范围，部分客户端可能对 198.20.x.x 不兼容。

⚠️ 注意 fake-ip-filter 不完整

当前只有 .lan、.local、geosite:cn 和几个自定义域名。建议补全常见本地设备域名（路由器、智能家居等）。

1.2 旁路由兼容性

🔴 关键 bypass_gateway_compatible 可能未开启

这是 OpenClash 专门为旁路由场景设计的选项。不开的话，其他设备通过 oect 转发的流量可能无法被正确拦截到 Clash 核心。

这很可能就是你电脑上不了 YouTube 的直接原因。

⚠️ 注意 IPv6 状态未确认

旁路由模式下不推荐开启 IPv6，可能导致 DNS 泄漏（IPv6 DNS 查询不经过 Clash）。除非主路由给 oect 分配了 IPv6 前缀并正确配置了 PD。

1.3 性能配置

配置项当前值推荐值说明
tcp-concurrent未启用true并行 TCP 连接，提升握手速度
find-process-mode未确认false路由器上关闭进程查找，节省 CPU
unified-delay未确认true统一延迟计算，选节点更准
global-client-fingerprint—已废弃改用 per-proxy 的 client-fingerprint

二、优化计划

修改前必须备份！ LuCI → OpenClash → 备份/恢复 → 导出配置。
修改后需重启 OpenClash 核心，可能短暂断网几秒钟。

Phase 1: DNS 优化（最关键）

在 YAML 的 dns: 段中修改：

dns:
  enable: true
  listen: 0.0.0.0:7874
  ipv6: false                    # ← 改：旁路由关闭 IPv6
  enhanced-mode: fake-ip
  fake-ip-range: 198.18.0.1/16   # ← 改：标准范围（原来是 198.20.0.1/16）

  # ← 新增：默认 DNS（仅解析 DNS 服务器域名，必须纯 IP）
  default-nameserver:
    - 223.5.5.5
    - 119.29.29.29

  # ← 修改：国内 DNS（改用 DoH 加密）
  nameserver:
    - https://doh.pub/dns-query
    - https://dns.alidns.com/dns-query
    - 223.5.5.5

  # ← 新增：国外 DNS（解析国外域名必须有）
  fallback:
    - tls://8.8.4.4
    - tls://1.1.1.1
    - https://dns.google/dns-query
    - https://cloudflare-dns.com/dns-query

  # ← 新增：Fallback 过滤（国内IP走nameserver，国外走fallback）
  fallback-filter:
    geoip: true
    geoip-code: CN
    geosite:
      - gfw
    ipcidr:
      - 240.0.0.0/4

  fake-ip-filter-mode: blacklist
  fake-ip-filter:
    - +.lan
    - +.local
    - +.localhost
    - geosite:cn
    # 你原有的自定义域名
    - +.km688.ink
    - +.onesubv.site
    - +.oneyyds.online
    - +.fengyyds.site
    - +.onemg.top
    - +.chybinc.com
    - +.invitevp.com
    - +.vp2.us
    # ← 新增：常见本地设备
    - +.mi.com
    - +.xiaomi.com
    - +.router.asus.com
    - +.tplinkwifi.net
    - +.speedtest.net
    - +.msftconnecttest.com
    - +.msftncsi.com

Phase 2: 旁路由兼容 + 性能

在 YAML 中与 mode: 同级的位置添加：

# ← 新增：性能优化
find-process-mode: false    # 路由器关闭进程查找，省 CPU
tcp-concurrent: true        # 并行 TCP 连接，提速
unified-delay: true         # 统一延迟计算

LuCI 界面设置（非 YAML）：

设置项位置值
bypass_gateway_compatibleOpenClash → 设置 → 模式设置1（开启）
intranet_allowedOpenClash → 设置 → 外部控制1
IPv6OpenClash → 设置 → DNS 设置关闭（除非主路由有 PD）

三、完整 DNS 段 YAML 参考

直接复制替换你 YAML 中的整个 dns: 段：

# ========================

# ========================
dns:
  enable: true

  fake-ip-filter:
    - +.lan
    - +.local
    - +.localhost

    - +.km688.ink

四、修改后验证清单

改完配置并重启 OpenClash 后，按顺序验证：

1
验证 DNS 解析
在你的电脑上执行： 
nslookup youtube.com 192.168.31.2
预期结果：返回 198.18.x.x 开头的假 IP ✅
如果返回 142.250.x.x（真实 IP）→ DNS 没走 oect ❌
2
验证 Fallback DNS
nslookup google.com 192.168.31.2
预期结果：返回 198.18.x.x 假 IP ✅
如果报错或超时 → fallback DNS 未生效
3
测试 YouTube 访问
浏览器打开 https://www.youtube.com
预期：正常加载 ✅
4
测试代理延迟
LuCI → OpenClash → 代理延迟测试
预期：主要代理组延迟 < 200ms ✅
5
检查 Clash 日志
ssh oect "logread | grep -i clash | tail -20"
预期：无 ERROR 级别日志 ✅

五、备份与回滚

📋 备份

修改前在 LuCI 中导出：OpenClash → 备份/恢复 → 导出配置

↩️ 回滚

如果改出问题：

  1. SSH 到 oect：ssh oect
  2. 停止 OpenClash：/etc/init.d/openclash stop
  3. 恢复备份：cp /root/openclash_backup.yaml /etc/openclash/config/*.yaml
  4. 重启：/etc/init.d/openclash start
📝 注意 重启 OpenClash 只影响代理功能（约 3-5 秒），不影响 Samba、aria2 等其他服务。如果重启后无法上网，等 30 秒通常会自动恢复（OpenClash 有 watchdog）。
