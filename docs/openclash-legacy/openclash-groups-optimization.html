二、发现的问题

2.1 🔴 服务分组缺少自动选优（最关键）

🔴 严重 所有 23 个服务分组都是纯 select（手动选择）

当前 YouTube 分组的逻辑：

YouTube:
  type: select              # ← 纯手动！
  proxies: [直连, 所有-手动, 所有-自动, 香港-自动, ...]

问题：你选了一个节点后，它永远不会自动切换。如果那个节点挂了或变慢，YouTube 就卡了。

影响范围：ChatGPT、Claude、GitHub、Telegram、Netflix... 全部 23 个分组都受影响。

2.2 🟡 缺失的分组

⚠️ 注意 5 个 rule-providers 没有对应的代理分组

Rule-Provider当前流量去向建议
Copilot / DomainMATCH → 其他新建 Copilot 分组
Gemini / DomainMATCH → 其他新建 Gemini 分组
Reddit / DomainMATCH → 其他新建 Reddit 分组
Nvidia / DomainMATCH → 其他可归入 Microsoft 或单独分组
Crunchyroll / DomainMATCH → 其他新建或归入 Anime 分组

2.3 🟡 其他-自动正则过长

⚠️ 注意 排除式正则 500+ 字符

# 当前：排除所有已知地区节点名称
filter: "^((?!(直连|拒绝|广港|香港|HK|Hong Kong|🇭🇰|HongKong|广台|台湾|...|🇺🇸|United States|英国|UK)).)*$"
# ← 维护困难，新节点加入其他地区时容易遗漏

建议：用排除式但保持简洁，或者改用包含式（只匹配"其他"关键字）。

2.4 🟡 Game 分组可以更智能

ℹ️ 提示 Game 当前是 select 手动选择

游戏对延迟敏感，建议改为 fallback（故障转移）模式：自动选延迟最低的节点，挂了立刻切下一个。

三、优化方案设计

将分组重新设计为 4 个层级：

Tier-1: 高频服务（自动选优 + 手动切换）

✅ 推荐 使用 url-test + 手动 fallback

目标服务：YouTube、ChatGPT、Claude、GitHub、Telegram、Google、Twitter

YouTube:
  type: url-test             # ← 自动选最快节点
  use: [IKUU, 三元]
  url: https://www.youtube.com/generate_204
  interval: 300
  tolerance: 50
  lazy: true
  proxies: [所有-自动, 香港-自动, 日本-自动]  # ← 手动备选

效果：平时自动选最快节点，你也可以手动切换到特定地区。

Tier-2: 媒体流（地区优先，按服务特性选）

服务推荐地区原因
Netflix香港-自动 / 新加坡-自动港区有独家内容
Disney+新加坡-自动 / 美国-自动东南亚内容库大
YouTube所有-自动 / 香港-自动速度优先
Spotify香港-自动 / 新加坡-自动曲库完整
TikTok美国-自动 / 新加坡-自动非中国区内容
HBO美国-自动 / 新加坡-自动内容库限制

Tier-3: 补全缺失分组

为 5 个有规则但没分组的 rule-providers 创建对应分组：

# 新增分组
Copilot:   { <<: *default }   # Microsoft Copilot
Gemini:    { <<: *default }   # Google Gemini
Reddit:    { <<: *default }   # Reddit
Nvidia:    { <<: *default }   # Nvidia
Crunchyroll: { <<: *default } # 动漫流媒体

# 对应规则中添加
- RULE-SET,Copilot / Domain,Copilot
- RULE-SET,Gemini / Domain,Gemini
- RULE-SET,Reddit / Domain,Reddit
- RULE-SET,Nvidia / Domain,Nvidia
- RULE-SET,Crunchyroll / Domain,Crunchyroll

Tier-4: 游戏低延迟

Game:
  type: fallback            # ← 故障转移模式
  use: [IKUU, 三元]
  url: https://www.gstatic.com/generate_204
  interval: 300
  proxies: [香港-自动, 日本-自动, 韩国-自动, 台湾-自动, 直连]

效果：自动选延迟最低的节点，挂了立刻切下一个，游戏不断线。

五、变更对比

变更项变更前变更后
服务分组类型 select（纯手动）×23 url-test（自动选优）×17
Game/Steam select fallback（低延迟故障转移）
缺失分组 5 个 rule-providers 无分组 补全 Copilot/Gemini/Reddit/Nvidia/Crunchyroll
懒加载 ❌ 未启用 lazy: true（不活跃时不测速）
YAML 模板 &default 单模板 &auto + &manual 双模板
服务分组地区偏好 全部相同（无差异） 按服务特性定制（Netflix→港/新，Game→日/韩）
影响的分组数 23 个服务分组 + 5 个新增 = 28 个分组变更
